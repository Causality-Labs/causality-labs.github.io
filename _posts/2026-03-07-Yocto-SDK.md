## Introduction

This is the fourth post in my Yocto blog series. In this post we will go over what a Yocto SDK is and how it is useful. Then we will use Yocto to create an SDK, then deploy it in a Docker Container. Once deployed in the container we will be able to use the SDK to develop our applications on our development machine and then copy it over to our target machine (FRDM i.MX91).

### What is a Yocto SDK

A **Yocto SDK** is a toolbox for building software for embedded Linux devices. It's like a complete workshop that gives you everything you need to write and compile programs for a specific device.

**What it contains:**
- **Cross-compiler**: Tools to compile code for your target hardware (like ARM processors)
- **Libraries and headers**: Pre-built software libraries your applications need
- **Debugger**: Tools to debug your code on the target device
- **Build tools**: Everything needed to compile and package your application

In simple terms: it's a box of development tools tailored specifically for your target hardware, so you can write and test embedded software on your laptop/desktop and then run it on your actual embedded device.

More details about the Yocto SDK can be found on the official [Yocto Documentation page](https://docs.yoctoproject.org/sdk-manual/intro.html). 

## How to build and deploy an SDK

### Building the SDK

First, source your Yocto environment so you can use `bitbake`:

{% highlight bash linenos %}
$ source setup-environment frdm-imx91/
{% endhighlight %}

Then run the command to build the SDK:
{% highlight bash linenos %}
$ bitbake -c populate_sdk <image-name>
{% endhighlight %}

Where `<image-name>` is the name of your target image (e.g., `core-image-minimal`, `core-image-sato`, etc.).

This command generates an SDK installer script in your build directory at `tmp/deploy/sdk/`. The script will be named something like `poky-glibc-host_system-image_type-arch-toolchain-release_version.sh`.

Where each variable represents:
- **host_system**: Your development system architecture: `i686` or `x86_64`
- **image_type**: The image for which the SDK was built: `core-image-minimal` or `core-image-sato`
- **arch**: The tuned target architecture: `aarch64`, `armv5e`, `core2-64`, `i586`, `mips32r2`, `mips64`, `ppc7400`, or `cortexa8hf-neon`
- **release_version**: The Yocto Project release number: `5.3.1`, `5.3.1+snapshot`, etc.

For my build it was called `fsl-imx-xwayland-glibc-x86_64-core-image-minimal-armv8a-imx91frdm-toolchain-6.6-scarthgap.sh`.

### Deploying the SDK

Once the SDK is built, you can deploy it to any machine (or Docker container) by running the installer script:

{% highlight bash linenos %}
$ chmod +x fsl-imx-xwayland-glibc-x86_64-core-image-minimal-armv8a-imx91frdm-toolchain-6.6-scarthgap.sh
$ ./fsl-imx-xwayland-glibc-x86_64-core-image-minimal-armv8a-imx91frdm-toolchain-6.6-scarthgap.sh
{% endhighlight %}

Follow the prompts to select an installation directory. The SDK will extract all necessary tools and libraries to that location.

## My SDK setup

Now we will go over how I use the SDK with Docker. By using the two together, I can replicate a consistent embedded Linux build environment that can be used across different applications. I compressed the SDK script and uploaded it as Github release. Note here that you can choose to store the SDK script locally or remotely. I chose to do it remotely so I can access it across various machines anywhere.

{% highlight bash linenos %}
$ tar -czf x86_64-imx91frdm-toolchain-6.6-scarthgap.tar.gz fsl-imx-xwayland-glibc-x86_64-core-image-minimal-armv8a-imx91frdm-toolchain-6.6-scarthgap.sh
{% endhighlight %}

### Publishing the SDK to GitHub

Once your SDK is compressed, you can publish it to GitHub as a release so it's easily accessible across machines.

#### Creating a GitHub Release

1. Navigate to your repository on GitHub
2. Click on **Releases** in the right sidebar
3. Click **Draft a new release** (or **Create a new release**)
4. Fill in the release details:
   - **Tag version**: Enter a version (e.g., `v1.0.0` or `sdk-6.6-scarthgap`)
   - **Release title**: Give it a descriptive name (e.g., `Yocto SDK for i.MX91`)
   - **Description**: Add notes about the SDK, build date, and usage instructions

#### Uploading the Tarball

5. In the **Attach binaries** section, click **Attach binaries by dropping them here or selecting them**
6. Select your compressed tarball file: `x86_64-imx91frdm-toolchain-6.6-scarthgap.tar.gz`
7. Click **Publish release**

Your SDK is now publicly available! You can download it from anywhere using:

{% highlight bash linenos %}
$ wget https://github.com/<your-username>/<your-repo>/releases/download/<tag-version>/x86_64-imx91frdm-toolchain-6.6-scarthgap.tar.gz
$ tar -xzf x86_64-imx91frdm-toolchain-6.6-scarthgap.tar.gz
$ chmod +x fsl-imx-xwayland-glibc-x86_64-core-image-minimal-armv8a-imx91frdm-toolchain-6.6-scarthgap.sh
$ ./fsl-imx-xwayland-glibc-x86_64-core-image-minimal-armv8a-imx91frdm-toolchain-6.6-scarthgap.sh
{% endhighlight %}

This approach ensures your SDK is version-controlled and easily shareable across all your development machines.

#### Docker Setup

Deploying the SDK in a Docker container ensures consistency across developers, simplifies setup, enables reproducibility, isolates dependencies, facilitates collaboration, and allows portability across Mac, Windows, and Linux machines. Instead of installing the SDK directly on each machine, developers can simply pull the Docker image and have a fully configured environment ready to use.

Here's a Dockerfile I use in my envsensord application [repository](https://github.com/Causality-Labs/envsensord) as a reference:

{% highlight dockerfile linenos %}
# i.MX91 Cross-compiler Environment for application.
FROM ubuntu:22.04

ARG SDK_URL="https://github.com/Causality-Labs/Yocto-SDKs/releases/download/v1.0.0/x86_64-imx91frdm-toolchain-6.6-scarthgap.tar.gz"

# 1. Install needed programs 
RUN apt-get update && apt-get install -y \
    make \
    openssh-client \
    python3 \
    xz-utils \
    file \
    wget \
    && rm -rf /var/lib/apt/lists/*

# 2. Retreive Yocto SDK toolchain (compressed)
RUN wget -q ${SDK_URL} -O /tmp/sdk.tar.gz

# 3. Deploy Yocto SDK
RUN cd /tmp && \
    tar -xzf sdk.tar.gz && \
    chmod +x fsl-imx-*.sh && \
    ./fsl-imx-*.sh -d /opt/fsl-imx -y && \
    rm -rf /tmp/sdk.tar.gz /tmp/fsl-imx*

# 4. Automatically source the SDK for interactive shells
RUN echo "source /opt/fsl-imx/environment*" >> /etc/bash.bashrc

# 5. Set working directory
WORKDIR /build
{% endhighlight %}

Build and run the Docker image:

{% highlight bash linenos %}
$ docker build -t yocto-sdk:imx91 .
$ docker run -it yocto-sdk:imx91
{% endhighlight %}

Now a developer can leverage the SDK to compile their application for a FRDM i.MX91 target.
